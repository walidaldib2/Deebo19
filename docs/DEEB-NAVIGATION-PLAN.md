# DEEB — الهيكل المقترح للأقسام والتنقل

تاريخ: 2026-11-24  
الفرع: `feature/deeb-premium-gold-ui-2026-11-24`  
الحالة: مقترح تنظيم قبل التطبيق؛ لا يغير أي شاشة أو سجل.

## الهدف

- واجهة بداية بسيطة على الهاتف.
- أحوال الطقس مختصرة وواضحة في البداية.
- كل وظيفة لها مكان أساسي واحد في التنقل.
- لا حذف للوظائف ولا تغيير لمصادر البيانات أو أسماء أنواع السجلات.
- الاختصارات الداخلية تفتح نفس الصفحة ولا تنشئ وظيفة مكررة.

## 1) الصفحة الرئيسية

تبقى البداية على `landing` وتحتوي على:
1. ملخص أحوال الطقس: درجة الحرارة والحالة والرطوبة والرياح ووقت آخر تحديث.
2. شريط بحث عام واحد.
3. خمس بطاقات رئيسية فقط:
   - لوحة التحكم
   - التشغيل الميداني
   - إدارة الأمن
   - التقارير والسجلات
   - البيانات والإعدادات

تُخفّف الزخارف والمساحات على شاشة الهاتف، ولا تظهر قوائم كل الوظائف دفعة واحدة. عند فتح أي قسم تختفي بطاقات البداية والبحث كما هو معمول به حاليًا، ويظهر زر رجوع واضح.

## 2) خريطة الأقسام المقترحة

### أ. لوحة التحكم
- مؤشرات سريعة: الفروع، أفراد الدوريات، الدراجات، البلاغات المفتوحة، المهام المتأخرة، حالات الطوارئ.
- آخر العمليات والتنبيهات.
- لا تنشئ نماذج أو سجلات جديدة؛ هي شاشة عرض واختصارات فقط.

### ب. التشغيل الميداني
- متابعة الفروع:
  - تشكيل الشفت اليومي.
  - متابعة الفروع.
  - حفظ سياق الشفت.
- مرور الدراجات:
  - تسجيل مرور جديد (`bikepatrol`).
  - خط سير يوم محدد (`map`).
  - خرائط الدراجات للفترة (`bikeMaps`).
  - تقرير خريطة الدراجة (`bikeMapReports`).
  - محذوفات مرور الدراجات (`bikePatrolDeleted`) من داخل سجل المرور.
- مرور المديرين.
- المهام والتكليفات.
- تسليم واستلام الشفت.

### ج. إدارة الأمن
- سجل الموظفين.
- الغياب والاستئذان.
- الحوادث والبلاغات.
- الطوارئ:
  - حالات الطوارئ.
  - أفراد الطوارئ.

### د. التقارير والسجلات
- مركز التقارير والتصدير والاعتماد.
- الأرشيف العام (مدخل أساسي واحد؛ زر الأرشيف داخل المركز يفتح نفس اللوحة).
- الإحصائيات.
- التقرير اليومي والمذكرات يظلان في «متابعة الفروع» كمدخل إنشاء وتعديل أساسي؛ مركز التقارير يعرضهما للطباعة والتصدير فقط، وليس مدخل إنشاء مكررًا.

### هـ. البيانات والإعدادات
- البيانات الأساسية:
  - الفروع.
  - أفراد الدوريات.
  - الدراجات.
  - مواقع المرور.
  - المديرون.
  - المستندات.
  - البيانات الإضافية.
- النسخ الاحتياطي والاستعادة.
- إعدادات الجهاز والحماية والإشعارات والتثبيت وQR وسجل المراجعة.

## 3) إزالة تكرار المداخل فقط

| الوظيفة | مكانها الأساسي المقترح | المدخل المكرر الذي يختفي |
|---|---|---|
| سجل الموظفين | إدارة الأمن | تبويب الموظفين داخل تسجيل البيانات |
| أفراد الطوارئ | داخل الطوارئ | تبويب أفراد الطوارئ داخل تسجيل البيانات |
| الأرشيف | التقارير والسجلات | المسار المستقل المكرر؛ يظل زر داخل مركز التقارير يفتح نفس الأرشيف |
| التقرير اليومي والمذكرات | متابعة الفروع (إنشاء وتعديل) ومركز التقارير (عرض/طباعة فقط) | لا يوجد نقل؛ هذا فصل بين إنشاء السجل وإخراج التقرير وليس تكرارًا للوظيفة |

إخفاء المدخل لا يعني حذف أي سجل. ستظل أنواع البيانات `employees` و`emergency_people` و`written_reports` و`memos` كما هي، وتظل كل القوائم والنماذج المرتبطة تقرأ من نفس المخازن.

## 4) قرارات مهمة بخصوص الوظائف المتشابهة

- لا ندمج تسجيل مرور الدراجة مع خريطة المرور؛ الأولى إدخال بيانات والثانية عرض خط سير.
- لا ندمج خريطة اليوم مع خرائط الفترة أو تقرير الخريطة؛ لها فلاتر ومخرجات مختلفة.
- لا ندمج التقرير اليومي مع المذكرة.
- لا ندمج الموظفين مع أفراد الدوريات؛ لكل نوع سجل واستخدام.
- لا ندمج أفراد الطوارئ مع الموظفين.
- لا نضيف تتبع GPS حي؛ الخرائط تعرض نقاط المرور المسجلة فقط.

## 5) خريطة الانتقال من الوضع الحالي

- `follow`: يحتفظ بتشكيل الشفت ومتابعة الفروع والتقرير اليومي والمذكرات كمدخل إنشاء وتعديل.
- `data`: يحتفظ بالبيانات الأساسية غير المتاحة في أقسامها التشغيلية؛ يخرج الموظفين وأفراد الطوارئ من قائمته.
- `operations`: يحتفظ بمتابعة الفروع ومرور الدراجات وخرائطها ومرور المديرين، ويضم المهام والتسليم.
- `security`: يحتفظ بالموظفين والغياب والبلاغات والطوارئ.
- `reportsGroup`: يضم مركز التقارير والأرشيف والإحصائيات؛ ويظل التقرير اليومي والمذكرات في متابعة الفروع، مع ظهورهما داخل مركز التقارير لأغراض الإخراج فقط.
- `system`: تدمج وظائفه تحت «البيانات والإعدادات» دون تغيير صفحة النسخ أو صفحة الإعدادات ذاتها.

## 6) شروط تنفيذ الهيكل

1. إنشاء اختبارات تتأكد أن كل route قديم ما زال يفتح بعد النقل.
2. التأكد أن كل نوع سجل يظهر في مكان واحد فقط كمدخل أساسي.
3. التأكد أن القوائم المرجعية ما زالت تقرأ من المصدر الأصلي نفسه.
4. اختبار إضافة وتعديل وأرشفة واستعادة كل نوع سجل.
5. اختبار كل الأزرار الداخلية التي تفتح الخرائط والتقارير والأرشيف.
6. اختبار البحث العام والرجوع إلى الرئيسية.
7. لا تُحذف المسارات القديمة قبل توفير تحويل آمن لها، ولا تتغير بيانات المستخدم.
8. تشغيل `npm test` وبناء Android بعد التعديل.
9. اختبار النسخة الناتجة على جهاز فعلي قبل اعتمادها.

## 7) خارج نطاق هذه المرحلة

- لا تغيير لمخطط IndexedDB أو أسماء المخازن.
- لا تغيير لحقول النماذج أو صيغ التقارير.
- لا حذف للبيانات القديمة أو المرفقات أو النسخ الاحتياطية.
- لا دمج إلى فرع `النسخة-وليد` دون موافقة صريحة.
