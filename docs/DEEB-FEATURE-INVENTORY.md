# DEEB — جرد الوظائف قبل إعادة تنظيم الواجهة

> هذا الجرد لقطة أولية من فرع التجربة `feature/deeb-premium-gold-ui-2026-11-24` بتاريخ 2026-11-24. لا يغيّر أي وظيفة أو بيانات. لا يُعتمد نقل أو حذف أي مدخل قبل استكمال مطابقة كل الأزرار والنماذج ومسارات الحفظ والتصدير.

## قواعد القبول الإلزامية
1. الحفاظ على كل وظيفة موجودة حاليًا وعلى بياناتها وسجلاتها ومرفقاتها.
2. لكل وظيفة مكان أساسي واحد فقط في التنقل؛ الاختصارات - إن لزمت - توجه إلى نفس الصفحة ولا تنشئ نسخة ثانية.
3. لا تُغيّر بنية قاعدة البيانات أو أسماء أنواع السجلات لمجرد إعادة ترتيب الواجهة.
4. الصفحة الرئيسية هادئة ومختصرة، وملخص الطقس ظاهر دون تكرار شاشة الطقس التفصيلية.
5. اختبار كل مسار وزر ونموذج وحفظ وتعديل وأرشفة واستعادة وتصدير قبل اعتماد أي تغيير.
6. فرع «النسخة وليد» يظل مستقلًا؛ لا دمج ولا استبدال دون موافقة صريحة.

## التنقل الرئيسي الحالي
- لوحة التحكم: `home`، والصفحة الخفيفة `landing` لملخص الطقس.
- التشغيل الميداني: متابعة الفروع، مرور الدراجات، خرائط الدراجات، مرور المديرين.
- إدارة الأمن: سجل الموظفين، الغياب والاستئذان، الحوادث والبلاغات، الطوارئ.
- التكليفات والمتابعة: المهام والتكليفات، تسليم واستلام الشفت.
- التقارير والسجلات: مركز التقارير، الإحصائيات.
- إدارة النظام: تسجيل البيانات، النسخ الاحتياطي والاستعادة، الإعدادات.

## صفحات ووظائف مسجلة في موجه التنقل
`landing`, `home`, `follow`, `emergency`, `map`, `bikePatrolDeleted`, `bikeMaps`, `bikeMapReports`, `bikepatrol`, `reports`, `employees`, `managerRounds`, `handovers`, `data`, `attendance`, `incidents`, `tasks`, `stats`, `archive`, `backup`, `settings`.

## أنواع السجلات/البيانات الموجودة في تعريف النماذج
- بيانات أساسية: `branches` الفروع، `employees` الموظفون، `patrol_people` أفراد الدوريات، `emergency_people` أفراد الطوارئ، `bikes` الدراجات، `patrol_sites` المخازن والمعارض ومراكز الخدمة، `managers` مديرو الأقسام، `documents` خزنة المستندات، `custom_data` بيانات إضافية.
- تشغيل ومتابعة: `daily_rosters` تشكيل الشفت اليومي، `branch_patrols` متابعة الفروع، `bike_patrols` مرور الدراجات، `manager_rounds` مرور المديرين.
- سجلات إدارية وتشغيلية: `written_reports` التقرير اليومي، `memos` المذكرات، `absences` الغياب والاستئذان، `incidents` البلاغات والحوادث، `tasks` المهام، `handovers` تسليم واستلام الشفت، `emergencies` حالات الطوارئ.

## التكرار المكتشف مبدئيًا ويحتاج قرار تنظيم
- `employees`: مدخل مستقل في «إدارة الأمن»، وموجود أيضًا داخل «تسجيل البيانات».
- `emergency_people`: داخل صفحة «الطوارئ»، وموجود أيضًا داخل «تسجيل البيانات».
- صفحة «مركز التقارير» تتيح فتح الأرشيف العام، ويوجد مسار مستقل `archive` يفتح نفس واجهة التقارير ثم يفعّل الأرشيف؛ يجب أن يبقى الأرشيف وظيفة واحدة لا نسختين.
- `bikeMaps` و`bikeMapReports` صفحتان مختلفتان: الأولى لعرض مسارات المرور المسجلة، والثانية لإخراج تقرير خريطة مستقل؛ لا ندمجهما قبل اختبار اختلاف الغرض.
- `map` تعرض نقاط المرور المسجلة حسب التاريخ والدراجة، بينما `bikeMaps` تعرض خرائط حسب نطاق زمني؛ يلزم فحص تداخل الوظائف قبل إعادة التسمية أو النقل.

## وظائف التقارير والتصدير المؤكدة من المصدر
- مركز التقارير: طباعة، PDF، حفظ التقرير صورة، Excel، CSV، تقرير شهري، تقارير منفردة حسب النوع، واعتماد نسخة التقرير.
- تقرير خرائط الدراجات: طباعة، PDF، حفظ صورة.
- تقارير مرور الدراجات والفروع والتقرير اليومي لها قوالب طباعة خاصة؛ يجب الحفاظ على تخطيط A4 والخطوط والأعمدة والتقسيم إلى صفحات كما هي.
- توجد معالجة أصلية لتصدير الصور والطباعة عبر إضافة Android أصلية، وليست مجرد زر واجهة.

## الخرائط والموقع
- خرائط Leaflet/OpenStreetMap، وعرض مسارات مبنية على نقاط GPS محفوظة في سجلات المرور.
- دعم فتح الملاحة الخارجية، ومشاركة/استقبال روابط مواقع Google Maps، وتحويل الروابط المدعومة إلى إحداثيات.
- يوجد التقاط للموقع الحالي عبر المتصفح/إضافة Android.
- **لا يوجد تتبع GPS حي مستمر** بحسب الشاشات والشرح الموجودين في الكود؛ الخرائط مبنية على نقاط المرور المسجلة.

## الطقس
- ملخص أحوال الطقس في صفحة `landing` مع تحديث يدوي وتحديد الموقع.
- مصدر البيانات Open-Meteo، والتحديث الدوري كل 30 دقيقة أثناء وجود الصفحة الرئيسية/الملخص في الواجهة والاتصال متاح.
- التفاصيل تتضمن الحرارة والرطوبة والرياح والمحسوسة. يجب اختبار انقطاع الإنترنت ورفض إذن الموقع وعدم توفر المدينة.

## الحماية والبيانات
- تخزين محلي عبر IndexedDB؛ الإعدادات توضح عدم وجود مزامنة سحابية أو حسابات فريق في هذه النسخة.
- PIN وبصمة عند دعم الجهاز، وقفل تلقائي عند انتقال التطبيق للخلفية إذا كانت الحماية مفعّلة.
- نسخ تلقائية محلية، وتنزيل نسخة JSON خارجية واستعادتها، وفحص مساحة التخزين وطلب الحماية من الإزالة.
- QR محلي، وسجلات مؤرشفة ومحذوفات لبعض الأنواع مع الاستعادة وفق سياسة الاحتفاظ.
- لا يجوز اعتبار النسخ المحلية حماية كافية عند فقد الهاتف؛ يجب الحفاظ على تحذير تنزيل نسخة خارجية.
