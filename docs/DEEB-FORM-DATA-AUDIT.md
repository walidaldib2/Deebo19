# DEEB — تدقيق النماذج وحقول البيانات

تاريخ التدقيق: 2026-11-24  
الفرع: `feature/deeb-premium-gold-ui-2026-11-24`  
النطاق: تعريفات `fields`، مولّد النماذج `formHTML`، ربط الأحداث في `renderEntity`، واختبارات قاعدة البيانات والواجهة.

## 1) سجل البيانات الأساسي وحقول كل نوع

| النوع | الحقول الأساسية في النموذج | ملاحظات الحماية والارتباط |
|---|---|---|
| `branches` | الاسم، الكود، العنوان، المسؤول، الهاتف، خط العرض، خط الطول، الحالة | يدعم تحديد الموقع؛ يستخدم في اقتراحات المتابعة |
| `employees` | الاسم، رقم ساب، الهاتف، الفرع، الوظيفة | الوظائف: مدير إدارة، مدير قسم، مشرف، مسؤول أمن |
| `patrol_people` | الاسم، الرقم الوظيفي، الهاتف، الفرع، الوظيفة، الحالة | مصدر اختيار أفراد تشكيل الشفت ومرور الدراجات |
| `emergency_people` | الاسم، التخصص، الهاتف، الفرع، التوفر | سجل أفراد الاستجابة |
| `bikes` | الرقم، الكود، النوع، الوصف، الفرد المسؤول، الحالة | مصدر اختيار الدراجات في التشكيل والمرور |
| `patrol_sites` | الاسم، نوع المكان، العنوان، الإحداثيات، ملاحظات | أنواع المكان: مخزن، معرض، مركز خدمة |
| `managers` | الاسم، القسم، الهاتف، الفروع التابعة | اقتراحات المشرفين والمسؤولين |
| `daily_rosters` | تاريخ الشفت، الشفت، البداية، النهاية، أفراد متعددون، دراجات متعددة | يحفظ معرفات الأفراد والدراجات، لا ينسخ سجلاتهم الأساسية |
| `branch_patrols` | الفرع، المشرف، المسؤول، التاريخ، الوقت، الحالة، الملاحظات، الشفت | يسمح بمتابعات متعددة للفرع في اليوم؛ ترتيب الفروع محفوظ محليًا |
| `bike_patrols` | الدراجة، الفرد، التاريخ، نوع المكان، المكان، وقت الوصول، رابط موقع، إحداثيات، ملاحظات | يختار الدراجة والفرد من السجلات الأساسية عند توفرها؛ يدعم رابط موقع واتساب |
| `manager_rounds` | المدير، القسم، الفروع، التاريخ، الوقت، النتيجة، الشفت | يمكنه استخدام سياق الشفت المحفوظ |
| `incidents` | النوع، التاريخ، الوقت، الفرع/الموقع، المسؤول، الأولوية، الحالة، الوصف، الإحداثيات، الإجراء، الشفت | يدعم إرفاق صور ومستندات |
| `tasks` | العنوان، المسؤول، الفرع، البداية، النهاية، الأولوية، الحالة، نسبة الإنجاز، الملاحظات، تاريخ العمل، الشفت | تظهر المهام المتأخرة والتنبيهات |
| `handovers` | تاريخ الشفت، المسلم، المستلم، المهام المفتوحة، البلاغات، الملاحظات، الإقرار، الشفت، التوقيع | يحفظ إصدارات متتابعة؛ التوقيع صورة مرسومة محليًا وليس توقيعًا إلكترونيًا موثقًا |
| `absences` | المسؤول الغائب، الوظيفة، الفرع، الشفت، التاريخ، السبب، البديل، الإجراء | سجل غياب واستئذان |
| `emergencies` | تاريخ الحالة، التصنيف، الموقع، الإحداثيات، الخطورة، المسؤول، الفريق، الحالة، الإجراءات، الشفت | يدعم تحديد الموقع |
| `written_reports` | العنوان، التاريخ، الشفت، القائم بالتقرير، نص التقرير | نموذج سردي مستقل؛ يظهر في متابعة الفروع ويصدر من مركز التقارير |
| `memos` | نفس حقول التقرير اليومي | نوع سجل مستقل ولا يدمج مع التقرير اليومي |
| `documents` | اسم المستند، التصنيف، المرجع، الملاحظات | يدعم مرفقات حتى 15 ميجابايت للملف |
| `custom_data` | التصنيف، الاسم، القيمة، الفرع، التفاصيل | بيانات إضافية مرنة |

## 2) الأزرار ومسارات الحفظ التي تم التحقق من وجود ربط لها

- نموذج السجل: إرسال وحفظ، إلغاء، سبب تعديل إلزامي عند التعديل، ورسالة نتيجة الحفظ.
- القوائم: إضافة سجل، تعديل، أرشفة، والبحث/التصفية المحلية.
- المواقع: التقاط GPS من إضافة Android أولًا ثم المتصفح عند الحاجة، مع عرض رسالة خطأ عند رفض الإذن أو انتهاء المهلة.
- مرور الدراجات: تحليل روابط المواقع المشتركة، تعبئة الإحداثيات، واختيار الدراجة والفرد من السجل الأساسي عند وجود بيانات مسجلة.
- المرفقات: تنزيل مرفق محفوظ؛ إضافة مرفق بعد حفظ السجل؛ حد 15 ميجابايت.
- التسليم والاستلام: رسم التوقيع ومسحه، عرض الإصدارات السابقة، مع حفظ إصدار جديد عند كل تعديل.
- النسخ: تنزيل JSON، استعادة ملف JSON، واستعادة نسخة تلقائية بعد تأكيد المستخدم.
- إعدادات الحماية: حفظ PIN، تفعيل/تعطيل القفل، تفعيل/تعطيل البصمة، مع رجوع PIN عند فشل البصمة.
- QR: إنشاء رمز ثم حفظه كصورة.
- التقارير: طباعة، PDF عبر شاشة الطباعة، صور، Excel، CSV، اعتماد نسخة، وطباعة النسخة المعتمدة.
- المحذوفات: استعادة بنود مرور الدراجات خلال مدة 30 يومًا.

## 3) ضوابط قاعدة البيانات التي تأكد وجودها

- تخزين محلي IndexedDB باسم `DEBOO16_LOCAL_DB` وإصدار قاعدة البيانات 3.
- مخازن منفصلة للسجلات، سجل المراجعة، التقارير المعتمدة، إصدارات التسليم، المرفقات، والنسخ التلقائية.
- عمليات الحفظ والتعديل والأرشفة والاستعادة تسجل أحداث مراجعة.
- تعديل سجل مؤرشف يحافظ على حالة الأرشفة وتاريخ الإنشاء.
- استعادة النسخة الاحتياطية تتحقق من صحة المعرّفات وعدم تكرارها، ومن ارتباط المرفقات وإصدارات التسليم بسجلات موجودة، وتتحقق من بيانات مرور الدراجات.
- قبل الاستعادة، يحاول التطبيق تنزيل نسخة احتياطية من الحالة الحالية إذا كانت هناك سجلات أو مرفقات.
- النسخ التلقائية تحتفظ بثلاث نسخ يومية محلية، وتُحدّث نسخة اليوم بعد تغييرات البيانات.
- لا توجد مزامنة سحابية أو قاعدة بيانات فريق في هذا التصميم المحلي.

## 4) فجوات الاختبار — لا تعتبر نجاح CI إثباتًا لاختبار الجهاز

الاختبارات الحالية قوية في فحص أجزاء كثيرة من الكود وتكامل IndexedDB، لكنها لا تضغط فعليًا على كل عناصر DOM في متصفح حقيقي. ما زال مطلوبًا:
1. اختبار كل نموذج بإضافة سجل ثم إغلاق التطبيق وفتحه والتأكد من بقاء البيانات.
2. اختبار كل نوع بتعديل سجل، ثم أرشفته، ثم استعادته، ومراجعة سجل الأحداث.
3. اختبار كل حقل اختيار عندما تكون القوائم الأساسية فارغة وعندما تحتوي بيانات كثيرة.
4. اختبار استعادة JSON على نسخة اختبار تشمل مرفقات وصورًا وتقارير معتمدة وإصدارات تسليم.
5. اختبار صلاحيات الموقع والبصمة والإشعارات والتخزين على جهاز Android فعلي.
6. اختبار طابعة فعلية، وحفظ PDF والصور وExcel وCSV وفتح الملفات الناتجة بتطبيقات Android المناسبة.
7. اختبار العربية والأرقام العربية والإنجليزية والتواريخ عند اختلاف إعدادات لغة الجهاز.

## 5) نقاط تحتاج قرارًا قبل تعديل الواجهة

- منع تكرار مدخل الموظفين وأفراد الطوارئ في التنقل، مع إبقاء مصدر البيانات نفسه.
- تحديد أسماء الأقسام النهائية ومكان «التقرير اليومي» و«المذكرة» و«الأرشيف» قبل تحريك أي مدخل.
- الإبقاء على الوظائف الثلاث لخرائط الدراجات منفصلة إلى أن يثبت اختبار الاستخدام أنها قابلة للدمج دون فقد.
- عدم تغيير أسماء أنواع السجلات أو حقولها أو مخازن IndexedDB في مرحلة إعادة التنظيم.

## 6) حالة التغيير

هذا الملف توثيق فقط. لم تتغير نماذج المستخدم أو قاعدة البيانات أو سجلاته، ولم يتم الدمج إلى «النسخة وليد».
